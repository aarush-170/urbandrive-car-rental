MongoDB document model (database urbandrive)

Green fields are plain references to MySQL rows. There is no cross-database foreign key; the API checks them.

vehicle_inspections

{
  booking_id:  Number,
  vehicle_id:  Number,
  type:        "pickup" | "return",
  inspected_at: Date,
  odometer:    Number,
  fuel_level:  String     // petrol/diesel cars
  or battery_percent: Number  // EVs
  damages: [               // 0..n items
    { part, severity: minor|moderate|major,
      note?, estimated_cost? }
  ],
  photos: [ filename ]
}
Indexes: (vehicle_id, inspected_at desc) · (booking_id, type) · damages.severity

vehicle_reviews

{
  booking_id:  Number,
  vehicle_id:  Number,
  customer_id: Number,
  category_id: Number,
  rating:      1..5,
  comment:     String,
  tags:        [ String ],
  created_at:  Date
}
Indexes: (vehicle_id, created_at desc) · (category_id, rating desc) · text index on comment and tags
Why documents: an inspection can have zero or five damages with different fields, and EVs record battery instead of fuel. A document with an embedded damages array avoids sparse columns and extra join tables. Aggregations used: average rating by category, damage count by severity, most-damaged vehicles, popular tags, and keyword search over reviews.
